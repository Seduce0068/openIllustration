# 運用ポリシー (Operational Policy)

本書は必須方針と現行プロトタイプの運用制約を定める。
設計決定は [ADR-0001](adr/ADR-0001-mvp-trust-boundaries.md) を参照する。

## 1. 認証・環境分離

- `ALLOW_MOCK_AUTH=1` はローカル開発・隔離テスト専用。本番環境では設定しない。
- `JWT_SECRET` は必須。32バイト未満は起動時に拒否する。十分な強度のランダム値を秘密管理基盤から注入し、ソース・ログ・配布物に含めない。
- `PINATA_JWT` 未設定時のモック動作は開発用途に限る。本番でモックCIDを保存しない。
- 本番起動時に必須設定の存在・形式・相互整合性を検査し、不正・不足設定ではfail closedで起動を拒否する。現行の設定確認だけでは本番要件を満たさない。
- JWT署名鍵、JPKI信頼情報、JPYC運用鍵等の保管者、最小権限、ローテーション、漏えい時失効・再発行手順を定める。秘密をログや監査公開データへ出さない。
- 指定マイナアプリ/JPKI認証を本番利用資格の必須条件とする。未認証者には利用させない。
- 実JPKI/マイナアプリの信頼検証が未完成の現行プロトタイプは、本番利用資格判定に使わない。

## 2. コンテンツ・個人データ

- 投稿バイト列、CID、チェックサム、ユーザーハッシュ、公開鍵、通報・投票記録を取り扱う。
- ユーザーハッシュは匿名化を保証しない。アクセス制御、保持期間、削除・訂正手続、バックアップ消去方針を本番前に定める。
- IPFSへの投稿は外部から取得可能になり得る。削除要請・違法コンテンツ対応・ピン解除の運用を整備するまで、永続公開を前提としたデータを安易に登録しない。
- アップロード形式・10 MiB上限・外部取得10 MiB上限を守り、コンテンツ内容の合法性をハッシュ検証で保証しない。

## 3. 監査・モデレーション

- MVPではDBを正本とする。3票以上で多数決し、現行実装は同数をApprovedとして扱う。
- 投票資格・選出、期限、異議申立て、法的削除要請への対応、BAN条件は未確定。本番運用前に責任者と手順を定義する。
- DB内監査ハッシュは現状の変更検知補助であり、必須要件の第三者検証可能な監査を満たさない。
- 本番前に署名鍵管理、監査対象・公開範囲、外部検証手段、個人情報保護、障害時運用を定めて試験する。

## 4. 支援・決済

- プラットフォーム内の有償取引・支援にはJPYCのみを必須の決済手段とする。他方式は提供しない。
- 閲覧のみの利用者にJPYC保有を求める方針ではない。
- 対応チェーン、トークンコントラクト、送金先変更、取引確認・最終性、手数料、返金・紛争の各運用を決定する。
- 模擬支援APIは501で無効化済み。取引記録は実決済の証明ではない。JPYC検証の実装時に決済APIへ置換し、模擬処理は再導入しない。

## 5. 運用準備・未整備事項

- 本番用のオリジンを定義し、CORSを環境設定する。ローカル開発オリジンを本番許可設定に流用しない。
- DBスキーマは起動時にバージョン管理マイグレーションで適用する（`_migrations` にchecksumを記録し、1ファイル1トランザクションで適用、前方のみでロールバックは提供しない）。失敗時は起動を中止し、失敗ファイルは適用されない。復旧は原因修正後の再起動とし、`_migrations` の記録を確認する。複数インスタンスの同時起動はマイグレーションが競合し得るため、本番展開前に排他手段（DBロック等）か単一ライター起動の運用を決定する。バックアップ、リストア手順も本番前に整備する。
- IPv6のみの制御をプロキシ経由で使う場合、信頼済みプロキシ以外の `X-Forwarded-For` を信用しない。ネットワーク層でも許可方針を実装する。
- ログにJWT、署名、個人情報、投稿本文、Pinataトークンを出さない。現在のエラー応答・観測性は本番要件を満たすか別途検証する。
- 起動時に設定を検証し、ヘルスチェック、メトリクス、アラート、障害対応・鍵ローテーション手順を整備する。グレースフル停止（SIGTERM/SIGINTで処理中リクエストを完了待ち）は実装済み。
- 本番配置前にliveness/readinessの意味、DB/IPFS/JPKI/チェーン依存障害時のreadinessを定義し、デプロイ・復旧訓練で確認する。

## 6. 本番移行ゲート

本番移行には、実JPKI認証の独立検証、JPYC取引確認と手数料・失敗時運用、第三者検証可能な監査、プライバシー・法務レビュー、モデレーション承認、IPFS削除/通報対応、DB復旧訓練、環境別設定とセキュリティ試験を必要とする。本書の記載だけで法令適合を保証しない。

## 7. 環境変数リファレンス

現行サーバーが読む環境変数の一覧。本番では開発専用の項目を設定しない。

| 変数 | 必須 | 既定 | 説明 |
| ---- | ---- | ---- | ---- |
| `JWT_SECRET` | 必須 | なし | HS256署名鍵。未設定・32バイト未満は起動を拒否する。秘密管理基盤から注入する。 |
| `DATABASE_URL` | 任意 | `file:local.db` | libSQL接続先。 |
| `DATABASE_TOKEN` | 任意 | 空 | リモートlibSQLの認証トークン。 |
| `ALLOWED_ORIGINS` | 任意 | 開発用オリジン3件 | CORS許可オリジン（カンマ区切り、`http(s)://` または `null`、末尾スラッシュは除去）。本番では必ず設定する。 |
| `PINATA_JWT` | 任意 | `mock_jwt`（模擬） | IPFSピン用トークン。未設定時は模擬動作となり、本番では使用しない。 |
| `RUST_LOG` | 任意 | `info` | ログレベルフィルタ。 |
| `EXPOSE_INTERNAL_ERRORS` | 開発専用 | 無効 | `1`/`true` で500系の内部詳細を応答へ含める。本番では設定しない。 |
| `ALLOW_MOCK_AUTH` | 開発専用 | 無効 | `1`/`true` で模擬JPKI・ゼロ署名を受理する。本番では設定しない。 |
| `ALLOW_IPV4_LOCALHOST` | 開発専用 | 無効 | `1`/`true` で127.0.0.0/8からのアクセスを許可する。本番では設定しない。 |

- 真偽値はいずれも `1` または `true`（大文字小文字を問わない）で有効になる。
- マイグレーションディレクトリの探索には開発便宜として `CARGO_MANIFEST_DIR` を参照する。
