## ADR-0008: モデレーション集計の第三者公開範囲

- Status: Accepted（プロジェクトオーナーの委任に基づくエージェント専門家判断）
- Date: 2026-11-21
- Scope: 認証済み利用者向け公開。未認証は 401。
- 実装段階: 本 ADR は公開範囲の決定のみ。段階2（公開ルート追加）は未実施。

## Context

DEC-04 は第三者検証可能な監査を本番要件とする。ADR-0005 は署名付き監査
エクスポートの形式と検証方式を決定したが、「公開範囲の最終判断は別 ADR
で決定する」と残していた（ADR-0005 決定7）。

現行の `GET /mod/stats` は `AuthClaims` 必須かつ `require_moderation_operator`
による認可であり、未認証は 401、未設定・未登録・BAN 済みの主体は 403 である。
この集計画面を一般利用者にも見せると、403 の権限エラーが一般画面へ漏れ、
「公開」と「運用者限定」の境界が曖昧になる（R1 分析の 403 不整合）。

## Decision

1. 公開範囲は認証済み利用者とする。未認証のリクエストは 401 で拒否する。
   既存の `require_moderation_operator` による認可境界は変更しない。
2. 公開する項目は次のホワイトリストに限る。
   - 件数: `reports` / `concluded` / `approved` / `rejected` / `quorum_not_met`
   - 月別 UTC 分布: `YYYY-MM` をキーとする月次件数
   - `generated_at`（集計生成時刻）
3. 公開しない項目は次とする。
   - 理由本文と理由の要約
   - CID、`user_hash`、通報者・投票者の識別情報
   - 個別行（通報・投票・確定のレコード）
   - 署名、監査エントリ、`content_audit_log` / `governance_audit_log`
   - BAN / UNBAN / UNPIN の件数（`bans` / `unbans` / `unpins`）
4. 段階2（認証済み利用者向け公開ルートの追加）は後続作業に委ね、今回は行わない。
   現行の `/mod/stats` は運用者限定のままである。

## ADR-0004 決定9 との優先関係

ADR-0004 決定9 は「通報件数、確定結果、理由の要約を公開する」と定める。
そのうち要約の公開は `GET /mod/reports` の認証済み利用者向け表示として既に
実装されている。本 ADR は集計レスポンスの公開範囲を規定し、要約を本 ADR の
ホワイトリストへ含めない。両者が衝突する場合は、公開範囲の最終判断として
本 ADR を優先する。ADR-0004 の他決定を廃止するものではない。

## 段階1のクライアント扱い

一般画面へ運用者向けの見出しと権限エラーが漏れる不整合を解消する。
クライアントは初期表示で `/mod/stats` を取得せず、中立的な文言のボタンが
押下されたときだけ認証付きでプローブする。200 応答というサーバ応答のみを
根拠に運用者パネルをマウントし、403 は一般画面へ描画せずにパネルを黙って
閉じる。固定文言とセンチネル検証は維持する。

## Consequences

- 認証済み利用者は個人情報を露出させない集計値だけを参照できる。
- 未認証は 401 で拒否され、閲覧を含む未認証利用を認めない方針と整合する。
- 段階2 が未実装のため、現時点で一般利用者が集計を取得できる経路はない。
- `quorum_not_met` は合計値のみで月次表には含めない既存契約を維持する。

## Alternatives

- **運用者限定のまま公開範囲を定義しない**: 透明性要件を満たさず不採用。
- **未認証へ集計を公開**: 閲覧を含む未認証利用を認めない方針と矛盾するため不採用。
- **理由の要約も集計へ含める**: 要約にも個人情報が残り得るため不採用。
- **監査スナップショットをそのまま公開**: 署名・監査エントリ・BAN 等を含むため不採用。
