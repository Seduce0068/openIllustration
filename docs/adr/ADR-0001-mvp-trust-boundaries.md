## ADR-0001: プロダクト原則と信頼境界

- Status: Accepted
- Date: 2026-10-14
- Decision owners: Project owner
- Scope: プロダクトと技術の基本方針

## Context

OpenIllustrationは、OSSによる反検閲性、高速・軽量な閲覧、ほぼゼロに近い利用者手数料を目指すイラスト・小説サイトである。本人確認、監査可能性、低コストな価値移転は、単なる任意の追加機能ではなく、なりすましや運営への過度な信頼を減らすための設計要素である。

現行コードはRust/Axum、Leptos CSR/Wasm、libSQL、Pinata/IPFSを用いたプロトタイプであり、実JPKI認証、JPYC決済、外部検証可能な監査、分散運用は完成していない。文書では目標要件と現時点の実装・保証を区別する。

## Decision

1. **プロダクト目的**: OSS、検閲耐性、高速性、軽量性、低手数料、クロスプラットフォーム性を最上位の設計目標とする。完全な検閲不能性・無停止・ゼロコスト・全環境での同一動作を保証する表現はしない。各目標の測定方法・受入値は別途定義する。
2. **本人確認・利用資格**: 指定されたマイナアプリ/JPKI認証をサイト利用資格の必須条件とする。認証できない利用者にはコンテンツ閲覧を含むサイト機能を提供しない。認証開始画面・認証開始API・運用ヘルスチェックのみ認証前アクセスを許容でき、コンテンツや利用者データを返さない。提示・署名・発行元・年齢属性等をサーバー側で検証し、検証済み認証トランザクションにセッションを暗号学的に結び付ける。本人確認済みと判断できない入力を認証済み扱いしない。開発モックは隔離環境限定で、未設定時は無効。
3. **決済**: プラットフォーム内の有償取引・支援を提供する場合、JPYCを必須の決済手段とする。カード等の代替決済を設けない方針とする。これは利用者が取引を行わない閲覧にもJPYC保有を要求する意味ではない。有償機能は許可チェーン・許可コントラクト上で取引要求に結び付いたJPYC送金を検証後に解放する。対応チェーン、最終性、ウォレット連携、手数料、返金・紛争手順は設計確定が必要。
4. **監査・ガバナンス**: 投稿・認証・モデレーション等の重要な操作を、第三者が検証できる監査設計にする。単一DB内のハッシュ連鎖だけではこの要件を満たさない。署名、連鎖形式、公開範囲、外部アンカー/台帳、訂正・削除要求との両立を詳細設計で決める。
5. **反検閲とモデレーション**: 単一の配信事業者や単一ゲートウェイへの依存を減らす。ただし反検閲性は違法・有害コンテンツ対応を無効化するものではない。モデレーション手続、異議申立て、公開性、配信・ピン解除の責任を定める。
6. **技術選定**: Rustを優先採用する。バックエンドはAxumを基準とし、共有ロジック・クライアント・運用ツールもRustで実現可能な範囲でRustを優先する。必要な外部仕様や運用性が優先される場合は例外を記録する。
7. **現状と目標の区別**: JPKI、JPYC、公開検証可能な監査、分散配信はプロダクト方針上の必須要件であるが、現行プロトタイプでは未完成である。未完成の間は利用可能な本番サービスとして告知しない。
8. **クロスプラットフォーム**: 利用者のOS・端末・ブラウザに依存しすぎないWeb利用を目指す。Rust/WasmやJPEG XLの採用自体を互換性の保証とみなさず、対応環境の定義、実機試験、機能差のフォールバックを設計する。JPKI連携とウォレット接続も対象環境で確認する。

## Consequences

- 以降の要件・設計は上記の方針を基準にし、単に実装がないことを理由に必須要件を対象外へ変更しない。
- 認証、監査、決済はそれぞれ明示された信頼境界・脅威・運用主体を持つ。
- 高速・軽量・低手数料の目標値、JPKI連携方式、監査アンカー、JPYC対応チェーン、分散ストレージ構成は設計上の未決事項として扱う。
- 対応OS・ブラウザ・端末、最小バージョン、JXLデコード経路、JPKIアプリ連携、ウォレット方式と互換性試験は未決事項として扱う。
- 本ADRは実装済み機能や法的適合の証明ではない。

## Alternatives

- **匿名・任意認証で開放する**: なりすましを抑えるため指定された本人確認を必須とする方針に反するため採用しない。
- **任意の決済手段を併設する**: JPYCを必須とする決済方針と、決済運用の単純化に反するため採用しない。
- **監査をDBだけに閉じる**: 運営者自身に対する検証可能性を提供できないため、最終要件として採用しない。プロトタイプの暫定実装としてのみ許容する。
- **Rust以外を一律禁止する**: 外部仕様・ツールとの適合を損ねる可能性があるため、「Rust優先」とする。

## Open Questions

- マイナアプリが返す証明・属性、認証開始方式、nonce結合、失効・発行元検証の具体仕様。
- JPYCの対応チェーン、最終性確認、必要確認数、誤送金・返金・手数料の扱い。
- 監査対象イベント、公開情報と個人情報の分離、署名鍵・外部アンカーの運用。
- 反検閲の脅威モデル、複数ゲートウェイ/ピン留め、コンテンツ削除と異議申立ての両立。
- 性能・バンドルサイズ・運用費・手数料の計測条件および受入値。
- 対応OS/ブラウザ/端末、アクセシビリティ、JXL表示フォールバック、JPKIアプリ起動・復帰、ウォレット接続の互換性基準。
