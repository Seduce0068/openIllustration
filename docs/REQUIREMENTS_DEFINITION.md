# 要求定義書 (Requirements Definition)

本書はOpenIllustrationの目的・要求を定義する。基本方針は
[ADR-0001](adr/ADR-0001-mvp-trust-boundaries.md) に記録する。

## 1. 目的

OSSとして公開・運営可能で、検閲耐性を備え、高速・軽量、クロスプラットフォームで、利用者負担の小さいイラスト・小説サイトを構築する。なりすまし等の不正を抑止し、本人確認・決済・重要操作を検証可能にする。

## 2. 成功条件

- 指定されたマイナアプリ/JPKI認証を利用資格の必須条件とし、確認できない利用者は利用できない。
- プラットフォーム内の有償取引・支援にはJPYCを必須とし、他の決済手段を提供しない。
- 重要操作の監査記録を運営者以外も検証可能な設計にする。
- 単一の配信経路・事業者への依存を減らし、障害・遮断時の代替経路を用意する。
- Rustを優先採用し、バックエンドはAxumを基準とする。
- PC・モバイル等の対象端末で主要機能を利用でき、特定OS・ブラウザに過度に依存しない。
- 性能・転送量・運用費・手数料の目標値を計測可能な受入条件にする。具体値は設計で決定する。

## 3. 対象機能

- JPEG XL静止画とMarkdown小説の投稿・閲覧。
- JPKIによる本人確認および必要な年齢属性の検証（DEC-01/DEC-02連携）。年齢/地域ポリシーは保守的既定値を持ちつつ運用者が構成可能とし、有効設定値（非秘密）は常に公開する。
- IPFS等のコンテンツアドレス方式と、複数配信経路による可用性・検閲耐性。
- 署名・監査可能性を備えた投稿、モデレーション、重要な状態遷移。
- JPYCを用いた利用者間の支援・有償取引。
- OSSとしてのソース、ビルド、運用、移行手順の公開。

## 4. 非目標・保証しない事項

- 絶対的な検閲不能性、常時稼働、ゼロ手数料。
- 本人確認を通過したことによる利用者の善意・コンテンツ合法性の保証。
- ハッシュ照合だけによる投稿者本人性、著作権、データベース管理者耐性の保証。
- チェーンやストレージの特性に依存する最終性・可用性を、アプリ単独で保証すること。

## 5. 現行実装との区別

現行コードはRust/Axum、Leptos CSR/Wasm、libSQL、Pinata/IPFSによるプロトタイプである。実JPKI連携、JPYC送金・検証、第三者検証可能な監査、分散運用は未完成であり、上記の必須要件を満たす本番システムではない。開発用モックを実認証・実決済として扱わない。

## 6. 受け入れと段階移行

各必須要件について、実装、試験、運用主体、障害時の代替策を対応付ける。JPKI・JPYC・監査の各機能はセキュリティレビューと運用手順を通過するまで本番有効化しない。性能・コスト・対応プラットフォーム目標値は計測と互換性試験に基づき別途合意する。
