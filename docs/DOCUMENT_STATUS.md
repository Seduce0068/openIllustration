# 文書・設計判断の確定状況

## 結論

プロダクトの必須方針は確定しているが、設計文書全体は最終確定していない。
文書は目標・現行実装・未決事項を区別したレビュー可能な状態であり、
本番要件の方式や受け入れ値には未決定事項が残る。

## 確定している方針

- OSSとして開発し、反検閲性、高速・軽量、クロスプラットフォーム性、
  利用者の低負担を目指す。
- 指定されたマイナアプリ/JPKI認証をサイト利用資格の必須条件とし、コンテンツ閲覧を含む未認証利用を認めない。認証開始とhealth確認は限定的な例外とする。
- 有償取引・支援にはJPYCのみを使う。閲覧だけにJPYC保有は要求しない。
- 重要操作は第三者が検証可能な監査設計とする。
- Rustを優先し、バックエンドはAxumを基準とする。
- 実装されていない機能を実装済み・本番対応済みとして扱わない。

## 現行文書の扱い

- [ADR-0001](adr/ADR-0001-mvp-trust-boundaries.md) はプロダクト原則を承認する。
  個別の認証、決済、監査、運用方式まで承認したものではない。
- 要件・設計文書は要求と目標設計を記録する。未実装箇所は
  [詳細設計書](DETAILED_DESIGN.md) と [テスト仕様書](TEST_SPECIFICATION.md)
  の状態表記を優先する。
- 本番化前に未決定項目をすべて解消し、実装、試験、運用承認の証跡を残す。
