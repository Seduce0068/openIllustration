# テスト仕様書 (Test Specification Document)

本書は現行プロトタイプの回帰テストと、必須要件のリリース受け入れテストを区別する。
JPKI、JPYC、第三者検証可能な監査は、実装前だからといって最終検証対象から除外しない。

## 1. テスト層

- **Unit**: `common` のチェックサム・年齢計算・監査ハッシュ等。
- **Integration**: Axumルーター、JWT認可、DB状態遷移、制約の検証。
- **E2E**: PlaywrightによるUIフロー確認。APIをモックするテストは実バックエンド統合を証明しない。

## 2. 実装済みテストの概要

| 領域 | 現行カバレッジ | 制約 |
| --- | --- | --- |
| 認証 | モックverify、無効トークン系、年齢判定のAPIテスト | 実JPKI/OID4VPの信頼検証は未テスト・未実装 |
| ネットワーク | IPv4拒否・IPv6許可のミドルウェアテスト | 実プロキシ、X-Forwarded-For偽装、WAFは未検証 |
| 完全性 | SHA-256一致・不一致、IPFS取得系のテスト | ゲートウェイ応答を完全に制御したサイズ・タイムアウト試験が不足 |
| Markdown表示 | raw HTMLをテキスト化してエスケープするユニットテスト | URLリンク先等の別途安全性検証は未記載 |
| モデレーション | 通報状態遷移、3票での多数決 | 重複・並行投票、同数、期限、異議申立ての試験が不足 |
| Upload | Content-Type判定のユニットテスト | 署名・実multipartサイズ境界・価格境界・実Pinata連携の試験が不足 |
| Support | 一部E2E/UIテスト | 実送金を行わず、決済成立の証明ではない |

## 3. 必須要件のリリースゲート

| ID | ケース | 期待結果 | 状態 |
| --- | --- | --- | --- |
| AUTH-01 | `ALLOW_MOCK_AUTH` 未設定 | モック認証とゼロ署名を拒否 | 追加テスト要 |
| AUTH-02 | 不正・期限切れJWT | 認証済みAPIが401を返す | 既存テスト範囲を確認・補強 |
| NET-01 | IPv4アクセスと開発ループバック例外 | 設定に応じて拒否/許可 | 一部実装済み |
| NET-02 | 信頼されないX-Forwarded-For | クライアント入力で接続元判定を迂回できない | 未実装・設計確定要 |
| CONTENT-01 | 許可外形式、負価格、非整数価格 | 400で拒否 | 追加テスト要 |
| CONTENT-02 | IPFS応答が10 MiB超過、遅延、切断 | 上限/タイムアウトを適用し、完全データとして返さない | 実装済み。試験要 |
| CONTENT-03 | SHA-256不一致 | コンテンツ描画を拒否 | 一部実装済み |
| CONTENT-04 | 小説に `<script>` 等のraw HTML | 要素として実行せず、文字列として表示 | 実装済み、回帰テストあり |
| MOD-01 | 同一ユーザーの同一通報への再投票 | 拒否 | 実装済み、回帰テスト追加要 |
| MOD-02 | 3人の異なる投票者による結果 | 規則通り状態遷移 | 一部実装済み |
| SUPPORT-01 | 0以下の支援額 | 拒否 | 実装済み、JPYC機能への置換要 |
| ID-01 | JPKI提示、署名、nonce、信頼元、失効の検証 | 有効な本人確認だけを受理 | 未実装、必須 |
| ID-02 | JPKI提示拒否・失効・期限切れ・再利用 | 保護機能を拒否 | 未実装、必須 |
| ID-03 | 認証トランザクションとJWT主体の結合 | 別セッション・クライアント申告IDで主体を偽装できない | 未実装、必須 |
| ID-04 | 未認証での閲覧APIアクセス | コンテンツ・監査等を拒否。認証開始・healthは許可 | JWT拒否実装。JPKI未実装 |
| PAY-01 | 対応JPYCの有効な送金と最終性確認 | 確認後のみ決済成立 | 未実装、必須 |
| PAY-02 | 非対応トークン、チェーン、再編成、二重通知 | 不成立または確認中として扱う | 未実装、必須 |
| PAY-03 | 取引要求ID・金額・受取先との不一致 | 有償機能を解放しない | 未実装、必須 |
| AUDIT-01 | 監査記録の改変・欠落・順序入替 | 独立検証で検出 | 未実装、必須 |
| PERF-01 | 初期表示、API、転送量、Wasmサイズ、手数料 | 合意済みSLO内 | 指標・閾値未決定 |
| COMPAT-01 | 対応OS/ブラウザ/端末で閲覧・投稿・認証・決済 | 対応マトリクスを満たし、安全なフォールバックを表示 | 環境・閾値未決定 |
| COMPAT-02 | JXL/Wasm非対応・機能利用不可環境 | 代替表示または案内。認証・決済は迂回不可 | 方式・環境未決定 |

## 4. 実行コマンド

```bash
cargo test --workspace
cd e2e && npx playwright test
```

E2Eは開発サーバー・モック設定の依存関係を明記し、CIでは再現可能な起動とクリーンなDBを使用する。実JPKI実機・JPYCテスト環境の試験計画は、対応仕様を確定した後に作成する。これらの必須ゲートを通過する前に本番利用資格判定・決済を有効化しない。

## 5. リリース証跡

リリースごとにテスト結果・ビルド成果物・依存ロックファイルを保存する。Nix再現可能ビルド、オンチェーン記録、バイナリ同一性の証明は別途設計・実装するまでリリース保証として主張しない。
