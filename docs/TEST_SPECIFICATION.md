# テスト仕様書 (Test Specification Document)

本ドキュメントは、本システムの各防衛ラインおよび論理設計が正しく動作することを検証するためのテスト計画を定義する。

## 1. テスト戦略

本システムは「ゼロトラスト」かつ「適正プロセス重視」であるため、以下の3つの観点でテストを実施する。

1. **セキュリティ検証 (Security Verification)**: 認証と制限の堅牢性確認。
2. **完全性検証 (Integrity Verification)**: コンテンツ改ざんの検知確認。
3. **ガバナンス検証 (Governance Verification)**: 陪審員制度のプロセス適正確認。

---

## 3. 実装・検証環境

* **検証環境**: Cloudflare Workers のプレビュー環境および Turso のステージングインスタンス。
* **自動テスト**: Rust の `cargo test` を使用し、認証・ハッシュロジックを単体テストする。
* **手動テスト**: 実際に有効なマイナンバーカードを用いたテスト認証フローの完走確認。

---

## 4. 真正性確認プロセス (Auditing)

すべてのシステムリリース時に、以下を実行して真正性を証明する。

1. **再現性のあるビルド**: `nix` 環境にて SHA-256 ハッシュを算出。
2. **オンチェーン記録**: 算出されたハッシュを VersionRegistry スマートコントラクトへ書き込む。
3. **公開検証**: GitHub の README に最新ハッシュを記載し、ユーザーが手元で検証可能であることを保証する。
